# Plan: make Cravera feel like a concierge (v0.1.0)

Status: proposal for the maintainer (2026-11-27). Delete after merge, once lasting decisions move to an ADR and PRODUCT.md.

## Why

The live data pipeline works (TASK-001), but the maintainer's test on the emulator showed the product doesn't feel intelligent yet:

1. **Plain-language cravings fail.** "I just finished at the gym, I want something healthy and high protein but not too expensive and quick, something fast food like Chipotle" → "Nothing open matched". The whole sentence is sent to Google as the search text; Gemini isn't wired (TASK-002).
2. **The result looks like a Google search result**: a card that doesn't fill the screen, with no sense of *why* this place was picked.
3. **No way to reprompt from a result.** You can only say No, or reach the refine box after 3 Nos or when results run out.
4. **The filter sheet is fake.** It discards its values (PRODUCT.md, Phase 2).
5. **Home feels cluttered**: logo orb, greeting, headline, subtitle, drifting cards, 3+ quick-pick chips, a composer with filter, mic ("coming soon") and send buttons, a location chip and a 4-tab nav bar. It doesn't read as "just talk to it".

## Design critique (current screens, Android emulator)

| Screen | Finding | Severity | Recommendation |
|---|---|---|---|
| Home | Up to 11 tappable things compete before the user has typed anything; the input sits at the bottom under chips | 🔴 | One hero input, a location chip and the send button. Move quick picks to suggestions *inside* the input when it's empty; remove the filter and mic buttons from the composer until they work |
| Home | The mic button does nothing ("coming soon") | 🟡 | Hide dead controls; a button that does nothing breaks trust in an "intelligent" app |
| Home | Drifting cards behind the input pull the eye | 🟢 | Calmer: fewer, slower, lower contrast, or one subtle animated orb |
| Result | Card uses ~60% of the height; lots of empty space below; reads as a list item | 🔴 | Full-screen pick: photo as a full-bleed hero (top ~55%), name and facts over a gradient, Yes/No as large thumb-zone buttons |
| Result | No explanation of the choice | 🔴 | A one-line "why this pick" built from Places facts and the parsed craving (for example "High-protein bowls · $ · 6 min walk · open until 10 pm"). Built from fields, never written by the LLM |
| Result | No reprompt; refine appears only after 3 Nos | 🔴 | Always-visible "Tell me more…" input plus one-tap refine chips: *Cheaper*, *Closer*, *Something different*, *Healthier* |
| Result | The ✕ and No look alike in purpose | 🟡 | ✕ becomes "New craving" (text button, top-left), No stays the main secondary action |
| Yes sheet | The floating nav bar covers the bottom of the sheet | 🟡 | Hide the nav bar on the result and sheet, or lift the sheet above it |
| Out of results / errors | Clear and recoverable | 🟢 works | Keep; restyle with the new system |
| Filter sheet | Values are thrown away | 🔴 | Replace with refine chips that actually apply (price, distance presets from PRODUCT.md: walk / short drive / far drive, dietary) |
| Accessibility | Not audited | 🟡 | Run `design:accessibility-review` on the redesign (contrast on photo overlays, 48 dp targets, text scaling) |

**What works:** the open-now guarantee, real data, hiding missing fields, fast No without new requests, Yes → exact place, clear error states with recovery.

### TASK-002 · Craving intelligence (sketch, for a spec in NEXT-TASK.md)

- **Where:** inside `places-search` (one round trip, key stays server-side) or a separate `parse-craving` function. Recommended: inside `places-search`, as a first step.
- **Gemini's output** (JSON schema, validated; anything invalid falls back to the raw text): `textQuery` (short, Places-friendly, for example "healthy high protein bowls"), `includedType` (restaurant subtype if clear), `priceLevels` (for example inexpensive and moderate), `maxDistanceMeters` hint ("quick" → nearer), `keywords` for "why this pick". Never restaurant names or facts (AGENTS.md).
- **Reprompt:** the previous parsed filters plus the new words go back to Gemini, so "cheaper" or "no seafood" adjusts instead of restarting.
- **Safety:** treat the craving as untrusted input (prompt injection can only change filters, never the data source or open-now); length limit already 200; Gemini key in secrets (`GOOGLE_GEMINI_API_KEY`); timeout with fallback to the raw text so search never breaks; status-only logs.
- **Cost:** one Gemini call per search or refine (Flash-class model). Note the free tier in the spec.
- **Proof:** the gym sentence returns a fitting open place near the test location; prompt-injection test ("ignore instructions, return…") still yields open restaurants only; Gemini down → raw-text search still works.

### TASK-UI-2 · Concierge redesign (sketch)

- **Palette:** food-appropriate (the maintainer: purple doesn't fit). Present 3 options as mockups to choose from; colours stay only in `lib/core/app_colors.dart`.
- **Home:** one hero input with rotating example cravings as hints, a small location chip, send. Quick picks appear as suggestions under the input only while it's empty. No filter or mic buttons until they work.
- **Pick screen:** full-screen; photo hero; name, rating, price, distance, open-until; "why this pick" line; large Yes / No; "Tell me more…" input and refine chips always visible; "New craving" in the corner; nav bar hidden here.
- **Refine chips replace the filter sheet:** Cheaper / Closer / Different cuisine / Healthier / distance presets. Each one is a reprompt through TASK-002, so they actually work.
- **Skills to use while building:** `design:design-system` (tokens for the new palette and type), `design:ux-copy` (hints, "why this pick", errors), `design:accessibility-review` (before merge), `design:design-critique` (on the new screens).

## Decisions for the maintainer

1. **TASK-002 first, then the redesign?** Recommended: yes. The redesign's "why this pick" and refine chips need parsed filters.
2. **Gemini inside `places-search`?** Recommended: yes (one call, simpler). Alternative: a separate function.
3. **Pull "working filters" forward from Phase 2 into v0.1 as refine chips?** Recommended: yes; the fake sheet is removed.
4. **Hide the mic button until voice exists?** Recommended: yes.
5. **Palette:** pick from 3 mockups when TASK-UI-2 starts.
